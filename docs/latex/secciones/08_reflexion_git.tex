\section{Parte 5: Preguntas de Reflexión sobre el Control de Versiones con Git}

\subsection{¿Por qué Git es crítico en proyectos colaborativos?}

En proyectos de software en equipo, Git es indispensable por cuatro razones técnicas:

\begin{enumerate}\setlength\itemsep{0.2em}
    \item \textbf{Desarrollo Concurrente y Paralelo:} Permite que varios desarrolladores trabajen simultáneamente en diferentes módulos (por ejemplo, Choquenaira en el motor de certificados, Yaranga en el control de asistencia y Ccama en el portal de inscripciones) mediante ramas independientes (\textit{feature branches}), sin interferir en la versión operativa.
    \item \textbf{Trazabilidad Total y Auditoría Histórica:} Cada commit deja una constancia inmutable con firma criptográfica que registra con exactitud quién modificó cada línea de código, en qué fecha y bajo qué justificación.
    \item \textbf{Revisión por Pares (\textit{Pull Requests / Code Reviews}):} Facilita que los cambios sean evaluados y aprobados por los compañeros antes de integrarse a la rama principal (\texttt{main}), elevando la calidad técnica del código.
    \item \textbf{Integración Continua (CI/CD):} Permite automatizar la ejecución de pruebas unitarias y el despliegue del sistema a entornos de prueba con cada fusión aprobada.
\end{enumerate}

\subsection{¿Qué problemas concretos evita?}

\begin{itemize}\setlength\itemsep{0.2em}
    \item \textbf{Sobrescritura accidental de código:} Elimina el riesgo de que dos personas editen un mismo archivo por medios informales (Drive, WhatsApp o USB) y uno borre inadvertidamente el trabajo del otro.
    \item \textbf{Caos de versionado manual:} Erradica la proliferación de carpetas como \texttt{SIGC\_v1}, \texttt{SIGC\_final}, \texttt{SIGC\_este\_si.zip}, reemplazándolo por un historial limpio con etiquetas semánticas formales (\texttt{v0.1.0}, \texttt{v1.0.0}).
    \item \textbf{Pérdida por fallos de hardware:} Al ser un sistema distribuido, cada clon local contiene el historial íntegro del proyecto. Si una máquina falla, el código se recupera instantáneamente desde GitHub o el equipo de un colega.
    \item \textbf{Reversión instantánea ante errores (\textit{Rollback}):} Si una funcionalidad causa fallas en producción, Git permite volver en segundos al último estado estable probado (\texttt{git revert}), asegurando la continuidad del servicio.
\end{itemize}
